# Desktop workspace: configure → choose a test → inspect

**Current decision — result priority, approved 2026-11-26:** the default wide view gives the main result the full workspace width. Configuration/test inputs and original request/response logs have explicit, reversible disclosures. This supersedes the earlier always-visible three-pane/equal-log layout described below. The target is a representative complete ordinary answer without manual scrolling, with full content retained for longer results.

## Earlier layout baseline (superseded defaults)

## Why change the layout?

There is one page, `index.html`, not separate routes for each vendor. Today `.container` stops at 1200px (360px unused per side at 1920). Configuration and test controls precede results inside a scrolling `.main-card`; widening that card alone leaves expanded settings above the output (`assets/css/styles.css:56–63,158–175,286–324,603–629`). Ordinary tests have two result columns. Capability and fingerprint modes **hide** those columns and show panels currently nested inside `.test-controls` (`index.html:142–372`; `styles.css:2162–2255`). A permanent three-way split between controls, messages and raw logs would waste a column in those modes.

## Wide layout (CSS viewport, not monitor resolution)

At **width ≥1600px and height ≥760px**, use a compact, left-aligned header with the existing title, description and local-storage note. Below it:

Width budget: 24px outside each edge, two 16px gutters; tracks `clamp(320px,18.34vw,352px)`, `clamp(392px,23.75vw,456px)`, `minmax(0,1fr)`. At 1600px the result still gets 808px. Cap the outer workspace at 1920px on larger displays. Use `100dvh` with `100vh` fallback and an **auto** header row; budget ~56px for the header, 32px total vertical padding and 12px gap. This leaves ~800 / 860 / 980px of workspace at viewport heights 900 / 960 / 1080 respectively. These are design targets, not measured screenshots. Extra height goes to reading, not larger controls.

## Boundaries, overflow and fallback

- Use nested grids: `.main-card` = configuration + `.test-section`; `.test-section` = test controls + result. Statically group the original `#fingerprintPanel`, `#capabilityPanel` and `.split-columns` as alternative result children after the controls. Keep their IDs, inner markup, `[hidden]`, inline visibility and body-mode rules authoritative. No cloning, DOM moves on resize, new controller or stored layout state. Replace the directional “上方配置 / 下方” helper with position-independent text. Behavior anchors: `assets/js/script.js:883–892,1190–1250,1618,2663–2759`, `capability.js:637–674`, `fingerprint.js:1705–1751`; retain the frontend hook, quality and proxy/profile contracts.
- Set shrinkable grid tracks/children (`min-height:0; min-width:0`). In wide mode the **config body**, **test form**, and each **visible result column** (or the one diagnostic panel) own vertical overflow; `.main-card`, `.split-columns` and the result wrapper must not add competing scrollbars. Let ordinary cards grow in the result column instead of capping every `pre` at 120px. Wrap JSON, URLs and errors; confine unavoidable horizontal scrolling to a table. Keep preview controls, copy buttons and focus rings clear of sticky headings. Limit completion auto-scroll (`script.js:500–512,4513`) to the timeline, never the form or page; respect reduced motion.
- Keep recent/model/effort lists with their field groups (`styles.css:1581,1738,2124`); in the wide rail use in-flow, height-limited lists so the last option is reachable, not clipped by the rail. The URL helper relies on `.url-input-wrapper` and outside-click handlers on the original groups. Keep `#configModal` and confirmation overlays outside pane clipping; retain the saved-config form/list and narrow modal scroll behavior.
- **Below either threshold**, release the pane height/scroll constraints and return to the familiar config → test → active result flow. Retain the existing two output columns above 900px and single-column inputs/results with document scrolling at ≤900px, including ≤600px and coarse-pointer rules. Zoom must trigger reflow, not smaller type. Keep system CJK text, monospace payloads, blue active states, visible focus, labelled keyboard-scrollable regions and existing live notices. No additional motion, fonts or dependencies. Local `ui-ux-pro-max --design-system` (no persistence) suggested a data-dense grid; its video hero, external fonts and amber CTA do not serve this workflow.

**Review / rollback:** Before shipping, use local fixtures only. At 1920×900, ×960 and ×1080, check Run/Stop and both ordinary output headings **without first scrolling**. Repeat with an expanded profile, image preview and long response. In capacity and manual fingerprint modes, expect the active panel title **instead of** the ordinary headings; scroll to the final attempt, sample or ranking without losing Stop. Tab to the last option/field and back to actions; verify no clipped focus, hidden active panel, scroll jump or horizontal page overflow. Recheck 1599px, short height, 375/768/1024/1440px and 200% zoom. Existing `tests/proxy-browser.e2e.mjs:1211–1231` checks reachability *after* scrolling, not first-screen fit. If a mode regresses, disable the wide media block to recover the base flow; the static grouping/copy and any timeline-only scroll adjustment can be reverted together without data migration.
