# 指纹库每日自动同步与部署

## Goal

每天自动检查模型指纹库上游，在兼容性和配套校验通过后自动提交数据与算法并部署本站，无需用户逐次手工同步；失败保留已验证的线上快照。

## Background

- 用户已选择“全自动更新”，授权本任务的 CI、同步脚本及浏览器版本加载改动；subagent 同时运行最多两个。
- 开发前使用 `Ikaleio/lm-detector` 固定快照 `1e58ed83c1cde17f88cba89560ad4d083042ae92`，63 模型；原同步器已有暂存构建及校验，但依赖旧版文件大小和特定模型预测。
- 开发前 Pages 工作流仅监听 main push / 手动触发；GITHUB_TOKEN 提交不会再触发 push 工作流，因此需显式衔接部署。
- 2026-11-25 核验上游 main 为 `e0472890bea827d15ca883636a77d4c10bbe843b`：bank/detector 为 76 模型、2026-11-23 构建；同 SHA conformance 为 72 模型、2026-11-17 构建，不满足配套校验，应拒绝。证据见 research/upstream-contract.md。

## Requirements

- R1：每天自动检查一次，并可手动运行；发现新版本后全自动校验、提交和部署。不要求人工合并或个人 PAT。
- R2：每次算法、数据、许可及验收样例均来自同一完整上游 SHA；允许模型数量和合法二进制大小变化，保留 schema、公开 API、80/3 采样协议、许可、数据配套及全部 conformance 验收门禁。
- R3：验收失败不覆盖已部署版本、不提交、不发布；不修改或重生成 expected 来放行不合格候选，错误需带明确上下文。
- R4：自动写入仅限现有五个指纹产物，无变化不创建提交，不强推、不绕过分支保护；构建验证时不持有仓库写入或 Pages 部署权限。
- R5：部署使用精确提交并防止过期构建覆盖新版；前次部署失败后，无新库时仍可恢复部署当前有效版本。
- R6：浏览器先获取版本清单，算法与数据按该版本加载和校验；缓存损坏及混版拒绝使用，单页已加载快照不在评分中被替换。保留懒加载、重试、手动评分、采样及取消。
- R7：交付使用说明，说明 GitHub 权限/分支规则、定时延迟限制、失败查看与整体回滚方法；不改远端设置或主动执行部署。

## Acceptance Criteria

- [x] 正常候选同 SHA 构建并通过完整校验；模型数和文件大小可合法演进
- [x] 当前旧快照可验证并迁移到带 bundle/license 摘要的清单；相同输入重复生成字节稳定
- [x] 当前上游陈旧 fixture 候选明确失败，五个现有产物保持不变
- [x] 离线回归覆盖有效更新、无更新、错误 fixture、损坏数据、接口/许可不兼容及失败不发布
- [x] 工作流只读验证、受限提交、Pages/OIDC 部署权限隔离；仅五产物可写，main 竞争及无变化逻辑可验证
- [x] 机器人提交后显式衔接精确 SHA 部署；所有发布使用 pages 锁，过期候选跳过，前次部署失败可恢复
- [x] 浏览器真实加载及缓存验证：无首次大文件请求、摘要破缓存、损坏/混版错误、当前指纹自动/手动/取消不回归
- [x] 使用说明、规范、任务记录及真实验证证据完整

验收范围为本地 CLI、隔离 Git 仓库、工作流解析与守卫执行、原生 Chrome。远端 Actions 权限、分支规则、Pages 环境和实际部署尚未执行验证；工作流需提交并推送到 main 后启用。当前最新上游未通过配套校验，本站继续保留已验证的 63 模型快照。

## Out of Scope

- 自动适配不兼容的上游算法或伪造通过验收
- 增加模型采样服务或调用真实模型 API 收集指纹
- 在浏览器直接追踪上游 HEAD 或定时替换正在使用的评分核心
- 修改账号权限/分支保护、添加 PAT、推送或部署本地实现（需用户后续明确要求）
